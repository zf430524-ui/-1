# 研学团负责人工作台：页面、字段、按钮与规则清单

- 文档状态：`APPROVED`
- 基线日期：2026-09-09
- 适用版本：本地单机负责人工作台 v1
- 需求来源：`研学团负责人工作台整合思路.md`
- 文档用途：与新版 PRD、`tasks.md` 和端到端验收标准共同约束页面职责、字段出现位置、按钮行为、校验、异常和跨模块联动。

> 本文是功能规格清单，不是 UI 视觉稿。页面布局可以调整，但字段归属、业务规则、状态变化和数据联动不得在画 UI 或开发时自行改变。

## 一、首版范围基线

### 1.1 使用对象

- 唯一操作角色：旅行社研学团负责人。
- 部署方式：公司本地电脑单机使用。
- 微信群继续承担导游招募、群二维码和接龙；工作台只生成可复制通知，并接收负责人复制回来的最终接龙名单。
- 首版不提供导游登录、导游移动端、在线报名、在线抢团、微信机器人或自动发群功能。

### 1.2 数据边界

| 数据模块 | 长期保存内容 | 明确不保存的内容 |
| --- | --- | --- |
| 学校库 | 学校名称、常用联系人、联系电话、合作备注 | 历次项目的年级、班级、老师和人数 |
| 导游库 | 导游基础资料、证件、有效期、合作状态、带团及退团事实 | 为每个项目重复复制一套导游档案 |
| 项目业务数据 | 项目、班级、老师、导游关联、车辆司机、项目随团人员汇总、乘车、住宿、用餐、导入导出和操作记录 | 独立车辆库、司机库、酒店库、房间库、餐厅库、学生个人名单 |

### 1.3 首版明确不做

- 不采集学生姓名、身份证号或个人名单。
- 不建立车辆、司机、酒店、房间、餐厅的跨项目资源档案。
- 不从微信群自动抓取接龙，不自动向微信发送通知。
- 不接保险公司接口；只导出保险名单 Excel。
- 不把任意 Word、Excel 或自由文本直接无确认地写入正式数据。
- 不把自动安排当作最终决定；系统只给建议、校验和异常说明，负责人最终确认。
- 不做支付、工资、发票、导游信用自动扣分或自动派单。

## 二、清单阅读规则

### 2.1 字段必填等级

| 标记 | 含义 |
| --- | --- |
| `创建必填` | 不填写则不能创建项目或档案 |
| `阶段必填` | 可暂时为空，但进入相应安排阶段前必须补齐 |
| `导出必填` | 可编辑安排，但生成正式表格前必须补齐 |
| `条件必填` | 仅在某个开关、状态或业务条件成立时必填 |
| `选填` | 不阻断流程，仅用于备注、检索或补充说明 |
| `系统生成` | 用户不可直接填写，由现有数据计算或记录 |

### 2.2 规则确定程度

- `已明确`：直接来自整合思路，后续 PRD 应原样承接。
- `建议默认`：为消除页面歧义而补充的可逆规则，写入 PRD 前由负责人确认。
- `待确认`：不同选择会明显影响流程或数据结构，不能在开发阶段自行决定。

### 2.3 全局交互约束

1. 所有阻断、警告和成功状态必须同时使用文字，不能只使用颜色。
2. 保存、导入确认、自动建议和人工调整后，都必须重新运行相关校验。
3. 表格中的错误必须定位到具体项目、班级、车辆、房间、餐次或字段。
4. 删除已被其他数据引用的记录时不得静默删除；应阻止删除或改为停用，并说明引用位置。
5. 未保存离开页面时显示二次确认；纯查看页面不提示。
6. 身份证号、导游证号和证件图片默认隐藏或脱敏；查看完整内容、修改和导出均记录操作日志。v1 不采集银行卡信息。
7. 没有住宿或用餐的项目，不显示对应执行入口，不创建空记录，也不提供空表导出。

## 四、全局状态与公共字段

### 4.1 项目状态

| 状态 | 出现条件 | 退出条件 |
| --- | --- | --- |
| 资料待补充 | 项目已创建但阶段必填资料不完整 | 班级、老师和项目条件资料达到下一阶段要求 |
| 人员安排中 | 已开始导入或安排导游 | 所需导游均已分配且无日期冲突 |
| 车辆安排中 | 已开始录入乘车安排 | 所有班级已安排且无超载或导出必填缺失 |
| 住宿安排中 | 多日且需要住宿，并已开始安排 | 住宿人数全部安排且无阻断异常 |
| 用餐安排中 | 项目含餐，并已开始安排 | 所有餐次达到桌数和人员安排要求 |
| 待检查 | 各适用模块已完成初步安排 | 阻断异常全部解决并由负责人确认 |
| 已完成安排 | 负责人完成最终检查 | 到达出团状态或重新编辑产生新异常 |
| 已出团 | 已开始执行 | 项目结束 |
| 已结束 | 项目已结束并保留历史安排 | 终态，不删除历史记录 |

规则：

- `已明确`：没有住宿或用餐时，不出现相应中间状态。
- `建议默认`：项目状态允许负责人手动推进，但推进至“已完成安排”前必须通过 P18 统一异常引擎的全项目阻断校验；完成后源数据变化也由同一引擎触发退回“待检查”。
- `建议默认`：已完成安排后修改人数、导游、车辆、住宿或用餐，系统自动退回“待检查”。

### 4.2 异常等级与处理状态

| 类型 | 示例 | 是否阻断完成/导出 |
| --- | --- | --- |
| 阻断 | 导游日期冲突、车辆超载、男女混住、人数未完全安排 | 是 |
| 警告 | 证件临期、车辆刚好坐满、存在跨班拼房 | 否，但必须显著显示 |
| 提醒 | 选填资料缺失、备注为空 | 否 |

异常状态：`待处理`、`已解决`、`已确认例外`。

- `建议默认`：只有警告和提醒可标记“已确认例外”，必须填写原因；阻断异常不能忽略。
- `已明确`：引起异常的数据被修改后应自动重算，不允许只改异常文字。

### 4.3 公共操作记录字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 操作时间 | 日期时间，系统生成 | 精确到秒 |
| 操作类型 | 枚举，系统生成 | 导入、查看敏感资料、修改安排、导出、备份、恢复 |
| 操作对象 | 文本，系统生成 | 项目、导游、导入批次、导出文件等 |
| 对象编号 | 文本，系统生成 | 用于跳回原记录 |
| 变更摘要 | 文本，系统生成 | 记录改了什么，不在日志中暴露完整敏感值 |
| 操作结果 | 枚举，系统生成 | 成功、部分成功、失败 |
| 失败原因 | 文本，条件生成 | 失败或部分成功时必有 |

## 五、逐页规格

## P01 今日工作台

### 页面目标与入口

- 登录本地工作台后的默认首页。
- 帮助负责人按“临近出团时间＋阻断严重程度”确定处理顺序。

### 展示字段

| 区域 | 字段 | 来源与规则 |
| --- | --- | --- |
| 近期项目 | 学校、年级、目的地、出团/结束日期、当前状态 | 来自项目；默认按最近出团日期排序 |
| 项目进度 | 班级资料、导游、车辆、住宿、用餐、检查完成度 | 未启用住宿/用餐时显示“不适用”，不显示 0% |
| 待办摘要 | 资料不完整、导游冲突、车辆超载、住宿容量不足、桌数不足 | 来自异常中心实时统计 |
| 证件提醒 | 导游姓名、证件类型、到期日期、剩余天数 | 只显示临期或已过期记录 |
| 数量指标 | 近期出团项目数、阻断异常数、待安排导游数、临期证件数 | 点击进入已筛选页面 |

### 按钮/操作

| 操作 | 可用条件 | 结果 |
| --- | --- | --- |
| 新建项目 | 始终可用 | 打开 P03 |
| 继续处理 | 项目未结束 | 进入 P04，并定位系统建议的下一阶段 |
| 查看全部异常 | 存在异常 | 进入 P18 |
| 查看导游档案 | 存在证件提醒 | 进入对应 P15 |

### 规则与状态

- 空状态：没有项目时显示“新建第一个研学项目”，不伪造指标。
- 当同一项目有多个问题时，项目只在近期项目列表出现一次，异常数量单独汇总。
- 首页不允许直接修改核心业务数据，只负责导航和提醒。

## P02 研学项目列表

### 页面目标

查找、区分并进入一个具体研学项目。

### 字段

| 字段 | 类型 | 可编辑 | 规则 |
| --- | --- | --- | --- |
| 项目编号 | 系统编号 | 否 | 唯一，创建后不变 |
| 学校 | 文本/学校关联 | 否 | 列表主标题 |
| 年级 | 文本 | 否 | 与学校一起显示 |
| 研学目的地 | 短文本 | 否 | 作为简短类目显示 |
| 出团日期 | 日期 | 否 | 列表排序依据之一 |
| 结束日期 | 日期 | 否 | 不得早于出团日期 |
| 行程类型 | 系统生成 | 否 | 同日为一日游，跨日为多日游 |
| 当前状态 | 枚举 | 否 | 使用 4.1 状态字典 |
| 阻断异常数 | 数字 | 否 | 0 时显示“无阻断” |
| 最近更新时间 | 日期时间 | 否 | 任一项目数据改变后更新 |

### 筛选与按钮

| 操作 | 规则 |
| --- | --- |
| 搜索 | 按学校、年级、目的地或项目编号检索 |
| 日期筛选 | 按出团日期范围筛选 |
| 状态筛选 | 支持多选；“已结束”默认不混入进行中列表 |
| 新建项目 | 打开 P03 新建模式 |
| 进入项目 | 打开 P04 |
| 编辑 | 打开 P03 编辑模式 |
| 结束项目 | 仅在负责人确认后执行；保留全部历史安排和记录 |

### 规则

- 首版不提供直接永久删除已产生安排或导出记录的项目。
- `建议默认`：仅无任何班级、导游、乘车、住宿、用餐和导出记录的误建项目允许删除。

## P03 新建/编辑项目

### 页面目标

允许负责人先用少量资料建项目，再逐步补全。

### 字段

| 分组 | 字段 | 类型 | 必填等级 | 来源/默认值 | 校验与显示 |
| --- | --- | --- | --- | --- | --- |
| 基本信息 | 学校名称 | 学校选择＋可新建 | 创建必填 | 学校库 | 新学校先建立最小学校记录 |
| 基本信息 | 年级 | 短文本/枚举 | 创建必填 | 手工填写 | 不写入学校库长期资料 |
| 基本信息 | 研学目的地 | 短文本 | 创建必填 | 手工填写 | 用于项目区分，避免录入冗长行程 |
| 日期 | 出团日期 | 日期 | 创建必填 | 无 | 不得晚于结束日期 |
| 日期 | 结束日期 | 日期 | 创建必填 | 默认等于出团日期 | 不得早于出团日期 |
| 日期 | 行程类型 | 只读 | 系统生成 | 日期计算 | 同日=一日游，跨日=多日游 |
| 集合 | 集合地点 | 文本 | 阶段必填 | 无 | 招募通知、执行资料使用 |
| 集合 | 集合时间 | 日期时间/时间 | 阶段必填 | 无 | 必须是有效时间；跨日项目只填首次集合时间 |
| 行程 | 行程内容 | 多行文本 | 阶段必填 | 无 | 不自动拆解成路线节点 |
| 规模 | 班级数量 | 正整数 | 阶段必填 | 由班级记录计算 | 与 P05 实际班级数一致 |
| 规模 | 项目学生总人数 | 非负整数，只读 | 系统生成 | P05 班级人数合计 | 不重复手填 |
| 联系人 | 学校总负责人 | 文本 | 阶段必填 | 可从学校联系人带入 | 只属于本项目，可覆盖带入值 |
| 联系人 | 负责人电话 | 手机/电话 | 阶段必填 | 可从学校联系人带入 | 格式错误时阻止进入待检查 |
| 条件模块 | 是否需要住宿 | 开关 | 条件必填 | 一日游默认否 | 只有多日游可开启 |
| 条件模块 | 是否含餐 | 开关 | 阶段必填 | 默认否 | 开启后显示用餐次数 |
| 条件模块 | 用餐次数 | 正整数 | 条件必填 | 无 | “是否含餐=是”时必填且大于 0 |
| 其他 | 特殊注意事项 | 多行文本 | 选填 | 无 | 在项目总览和相关安排页显示 |

### 按钮/操作

| 操作 | 结果与规则 |
| --- | --- |
| 保存草稿 | 创建必填通过后保存；资料不完整时状态为“资料待补充” |
| 保存并补充班级 | 保存后进入 P05 |
| 取消 | 无未保存内容时直接返回；有改动时二次确认 |
| 结束项目 | 仅编辑模式出现；进入终态前执行最终确认 |

### 关键规则

- `建议默认`：行程类型不让用户重复选择，由出团和结束日期自动计算，避免日期与类型矛盾。
- 出团日期改动后必须重新校验所有导游日期冲突，并检查住宿启用条件。
- 多日改成一日时，如果已经存在住宿数据，禁止直接保存；必须先确认删除住宿安排及影响。
- 含餐从“是”改为“否”且已存在用餐数据时，禁止静默删除，必须显示影响数量并二次确认。

## P04 项目执行总览

### 页面目标

作为单个项目的统一入口，展示资料完整度、适用模块、异常和下一步。

### 展示字段

| 区域 | 字段 |
| --- | --- |
| 项目抬头 | 学校、年级、目的地、日期、行程类型、项目状态 |
| 核心统计 | 班级数、学生数、项目随团人员汇总、所需导游数、已安排导游数、车辆数 |
| 条件统计 | 需要住宿、住宿人数/已安排人数；含餐、餐次数/已配置餐次数 |
| 资料完整度 | 缺失字段数量及可点击明细 |
| 异常摘要 | 阻断、警告、提醒数量 |
| 阶段入口 | 班级老师、招募接龙、导游安排、乘车、住宿、用餐、表格 |

### 按钮/操作

- 编辑项目资料：进入 P03。
- 导入资料：进入 P11，自动带入当前项目。
- 继续下一步：进入第一个未完成且适用的执行模块。
- 重新校验全部：重算导游、车辆、住宿、用餐和导出条件。
- 标记已完成安排：仅无阻断异常且适用阶段均完成时可用。
- 查看随团人员来源：进入 P05 汇总区；老师、导游和司机必须显示来源模块及回改入口。

### 显示规则

- 一日游或“不需要住宿”时隐藏住宿入口，并标记为“不适用”。
- 不含餐时隐藏用餐入口，并标记为“不适用”。
- 阶段完成不代表没有警告；警告仍在项目抬头持续显示。

- 项目学生总人数 = 所有班级学生总人数之和。
- 任一班级人数改变后，车辆空位、住宿未分配人数、用餐建议桌数和表格预览立即失效并重新计算。

- 首版不出现学生个人名单入口。

## P07 导游安排

### 页面目标

| 档案匹配状态 | 系统生成 | 已匹配、待确认、未建档、资料不一致 |

| 日期冲突 | 系统生成 | 显示冲突项目及重叠日期 |

| 默认参加餐次 | 项目级开关/多选 | 项目含餐时条件必填；默认全餐次，可按项目调整 |

### 按钮/操作

| 操作 | 可用条件 | 结果 |
| --- | --- | --- |
| 按顺序生成建议 | 匹配完成且存在未分配班级 | 只生成初步建议，不自动确认最终安排 |
| 保留/移出 | 名单人数超过需求时 | 改变项目名单状态；不删除导游档案 |
| 分配班级 | 无日期冲突且档案可用 | 关联导游与班级 |
| 允许负责两个小班 | 负责人主动选择 | 强制填写原因，并重新校验班级覆盖 |

### 阻断规则

- 导游在项目完整日期闭区间内与其他项目重叠时禁止分配。

- 默认一个导游只能负责一个班级；双班例外必须人工触发并留原因。
- 所有要求导游的班级未覆盖时，项目不能进入“待检查”。
- 导游分配、退团、替换或参与标记变化后，P05 项目随团人员汇总及 P09/P10 立即重算。

### 已确认规则

- “临近出团退团”按距离出团 3 天及以内计算；同时保留原始天数便于追查。

## P08 乘车安排

### 页面目标

记录当前项目的车辆与司机，按班级安排乘车并持续校验核载。

### 车辆级字段

| 字段 | 类型 | 必填等级 | 校验 |
| --- | --- | --- | --- |
| 车号 | 短文本 | 导出必填 | 同一项目内唯一 |
| 车队名称 | 文本 | 导出必填 | 仅当前项目使用 |
| 车辆型号 | 文本 | 导出必填 | 不建立车型库 |
| 可用座位数 | 正整数 | 阶段必填 | 必须大于 0 |
| 车牌号 | 文本 | 导出必填 | 同一项目内不应重复 |
| 司机姓名 | 文本 | 导出必填 | 与电话成组 |
| 司机电话 | 手机/电话 | 导出必填 | 格式校验 |
| 司机性别 | 枚举 | 条件必填 | 项目需要住宿且司机住宿时必填 |
| 司机是否住宿 | 开关 | 条件必填 | 项目需要住宿时必须明确 |
| 司机默认参加餐次 | 开关/多选 | 条件必填 | 项目含餐时必须明确；默认可选择全部餐次 |
| 备注 | 多行文本 | 选填 | 当前项目使用 |

### 乘员分配字段

| 字段 | 类型/来源 | 规则 |
| --- | --- | --- |
| 班级 | 班级关联 | 一个车辆可包含多个班级分配行 |
| 班级学生总人数 | P05，只读 | 用于对照原始人数 |
| 本车学生人数 | 非负整数 | 不拆班时等于班级学生总人数；拆班时填写实际人数 |
| 男生/女生人数 | P05 或分配值 | 拆班时两项之和必须等于本车学生人数 |
| 班主任及电话 | P05，只读 | 随班级带入 |
| 配班老师及电话 | P05，只读 | 随班级带入 |
| 随车老师人数 | 非负整数 | 参与核载 |
| 研学导游及电话 | P07，只读/选择 | 参与核载，不复制导游档案敏感字段 |
| 导游人数 | 系统生成 | 按本车已关联导游计数 |
| 乘车人数 | 系统生成 | 学生＋随车老师＋导游 |
| 空车位 | 系统生成 | 可用座位数－乘车人数 |

### 按钮/操作

- 导入乘车表：进入 P11/P12，资料类型锁定为乘车安排。
- 新增车辆：新增当前项目车辆记录。
- 生成安排建议：遵循一班一车、尽量不拆班、按班级顺序、减少座位浪费、尽量同车队。
- 移动班级/调整人数：人工修改分配后立即重算。
- 拆分班级：建立多个乘员分配行，必须保证各车学生人数合计等于班级总人数。
- 合并乘车：允许多个班级进入同一车，仍须逐班保留人数。
- 删除车辆：车辆仍有乘员时禁止直接删除，需先移出或重新分配。
- 校验全部：列出超载、未安排、拆分不平、必填缺失。

### 规则

```text
乘车人数 = 本车学生人数 + 随车老师人数 + 导游人数
空车位 = 可用座位数 - 乘车人数
```

- 空车位可以为 0；小于 0 为阻断异常。
- 同一个班级在多车的学生人数合计必须等于 P05 学生总人数。
- 同一导游不能被重复计算到多辆车；跨车任务需要先明确其实际乘车车辆。
- 司机及其住宿/用餐参与标记自动进入 P05 项目随团人员汇总；修改后联动 P09/P10。
- 自动建议每次运行都覆盖前先展示影响，不静默替换人工安排。

- 可用容量可大于住宿人数，不要求住满。
- 人工调整后，原建议状态变为已修改并重新校验。

### 已确认规则

- P05“项目随团人员汇总”是统一来源；不得另建 P09 工作人员人数表。

### 启用条件

- 不含餐时入口隐藏、不创建数据、不生成空表。

| 餐次名称 | 短文本 | 阶段必填 | 如第一天午餐 |
| 餐厅名称 | 文本 | 阶段必填 | 只属于当前项目 |
| 用餐时间 | 日期时间 | 阶段必填 | 应落在项目日期范围内 |
| 每桌标准人数 | 正整数 | 阶段必填 | 默认 10 |

- 学生来自 P05 班级人数；已安排导游来自 P07；老师来自 P05；司机来自 P08；摄影师和其他角色来自 P05 项目随团人员汇总。
- 默认参加本餐的人数按各来源的餐次参与标记汇总。单餐增减必须记录角色、差异人数和原因，并在 P18 留下可追查异常/确认记录。
- 任一来源缺失或汇总不自洽时，不允许把该餐次标记为完成。

### 就餐分配字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 桌号 | 文本 | 同一餐次内唯一 |
| 班级 | 班级关联 | 学生用餐时必填 |
| 人员角色 | 枚举 | 学生、导游、老师、司机、摄影师、其他 |
| 安排人数 | 正整数 | 同桌合计不得超过每桌标准人数，除非负责人明确修改标准 |
| 拼桌班级及人数 | 可重复子表 | 拼桌时分别记录各班人数 |
| 拼桌说明 | 文本 | 拼桌时条件必填 |

- 新增餐次：餐次数不得超过 P03 设置的用餐次数，除非先修改项目。
- 导入用餐表：进入 P11/P12。
- 生成桌数建议：显示学生、导游、老师、司机人数及计算口径。
- 生成就座建议：班级按顺序、同班桌号连续，不足十人可与后一班拼桌。
- 人工调整：移动人数或桌号后重新校验。
- 校验全部：检查餐次缺失、桌号重复、桌数不足、人员遗漏或超桌容量。

### 已确认规则

- `已明确`：学生和导游按每桌十人计算；老师、司机、摄影师和其他工作人员从统一随团人员汇总单独统计并由负责人安排。
- 基础建议桌数采用 `向上取整((学生人数＋导游人数) / 每桌标准人数)`；其他工作人员不计入基础建议值，但必须在页面单独显示待安排人数，由负责人人工追加桌数，最终总容量覆盖本餐全部参加人员。
- 其他工作人员占用同一批实际预订桌数；人员来源统一使用 P05 项目随团人员汇总。

- 去处理：跳到具体页面并定位对象。
- 重新校验：从源数据重新计算。
- 确认例外：仅警告/提醒可用，填写原因。
- 查看已解决：默认折叠，支持追查。

### 规则

- 不允许在异常中心直接手工把阻断状态改为已解决；必须修正源数据。
- 同一问题重复校验时更新现有异常，不制造大量重复记录。
- 源问题再次出现时重新打开异常并记录时间。

## P19 导入、导出与操作记录

### 页面目标

追查资料来源、批量处理结果、敏感操作和导出历史。

### 导入记录字段

- 原始文件名或“粘贴文字”。
- 导入时间、目标项目、资料类型、导入方式。
- 成功条数、失败条数、跳过条数。
- 结果：成功、部分成功、失败。
- 错误原因和失败行下载/查看入口。

### 导出记录字段

- 项目、表格类型、导出时间、文件名、结果。
- 数据版本时间或生成时项目最近更新时间。
- 敏感导出用途说明（保险名单时必填）。
- 失败原因。

### 操作记录字段

- 使用 4.3 公共字段。
- 支持按时间、项目、操作类型和结果筛选。

### 规则

- 日志中不记录完整身份证号、导游证号或证件图片地址。
- 首版单机只有一个负责人角色时，操作者显示本机负责人；若未配置姓名则显示“本机负责人”，不能伪造多人账号。
- 记录不可在普通页面删除或编辑。

## P20 本地备份与恢复

### 页面目标

让负责人能备份和恢复 SQLite 数据库及证件图片目录，并明确备份是否完整。

### 字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 数据库位置 | 只读路径 | 不允许页面直接打开编辑数据库 |
| 证件目录位置 | 只读路径 | 受本地访问权限保护 |
| 最近备份时间 | 系统时间 | 无备份时明确显示“尚未备份” |
| 最近备份结果 | 枚举 | 成功、部分成功、失败 |
| 今日已校验备份 | 布尔/时间 | 仅成功且完整性校验通过才记为“是” |
| 备份文件位置 | 只读路径 | 不与普通 Excel 导出目录混放 |
| 备份内容 | 多选 | 数据库、证件图片；默认两者全选 |
| 备份备注 | 文本 | 选填 |
| 恢复文件 | 文件选择 | 恢复时必填 |
| 保留策略 | 只读说明 | D08 推荐值为最近 30 个日备份＋12 个按月备份 |
| 清理结果 | 枚举/说明 | 未运行、成功、部分失败；显示保留与清理数量 |

### 按钮/操作

- 立即备份：先检查目标位置，再生成完整备份并校验文件存在。
- 打开备份位置：打开本地目录，不暴露为网络共享。
- 校验备份：检查数据库和证件目录清单是否完整。
- 从备份恢复：高风险操作，先显示备份时间和将覆盖的当前数据，要求二次确认。
- 恢复前备份当前数据：默认勾选，不允许无提示覆盖。
- 退出应用：当天无成功且已校验备份时，显示“立即备份并退出 / 暂不退出 / 仍然退出”；仍然退出需二次确认并记录。

### 规则

- 恢复属于可覆盖当前数据的高风险操作，必须写入操作记录。
- 备份文件应设置本地访问权限，不与普通导出表格混放。
- 只有新备份完整性校验成功后才执行轮转清理；最新可用备份不得被删除，清理失败不得破坏新备份。
- 每日首次退出前提醒备份；保留最近 30 个日备份和 12 个按月备份。D06 公司保留要求优先，具体受限目录由技术方案确定。

## 七、页面级空状态、错误状态和恢复动作

| 场景 | 页面表现 | 可执行动作 |
| --- | --- | --- |
| 无项目 | 工作台和项目列表显示明确空状态 | 新建项目 |
| 项目资料不完整 | 显示缺失字段和所属阶段 | 跳到 P03/P05 补充 |
| 导入无法识别 | 不写正式数据，显示原始列和错误原因 | 手工映射、换模板、取消 |
| 只有部分行有效 | 显示成功/失败数量和具体失败行 | 修正全部或仅导入有效行 |
| 接龙人员未建档 | 标记未建档，不进入正式安排 | 新建档案后返回匹配 |
| 自动安排无解 | 不生成虚假的“完成”结果 | 显示缺口、保留未安排项、人工调整 |
| 条件模块不适用 | 页面入口隐藏或显示“不适用” | 修改项目条件后启用 |
| 导出被阻断 | 列出具体缺失和异常 | 跳转修正后重新检查 |
| 文件生成失败 | 显示失败原因，不记录为成功导出 | 重试、修改保存位置 |
| 恢复失败 | 当前数据不应被半覆盖 | 回滚到恢复前自动备份并显示错误 |

## 八、已写入新版 PRD 的确认决策

负责人于 2026-09-09 确认以下规则，实施时不得自行改回候选口径：

1. “临近出团退团”按距离出团 3 天及以内计算。
2. P05“项目随团人员汇总”是工作人员住宿和用餐的唯一来源；老师/P07 导游/P08 司机自动汇入，摄影师和其他角色手工汇总。
3. 老师、司机及其他工作人员占用同一批实际预订桌数，由负责人按单列人数人工追加桌数，最终容量覆盖全部就餐人员。
4. 项目状态采用“负责人手动推进＋系统阻断门禁”。
5. 导入存在错误行时允许只导入有效行，但必须记录为部分成功并保留失败原因。
6. 有历史引用的数据不硬删除；无引用误建数据可删除；真实数据保留周期在投入使用前另行确认。
7. 证件到期前 30 天提醒。
8. 每日首次退出前提醒备份，保留最近 30 个日备份和 12 个按月备份；具体受限备份目录由技术方案确定。
9. “好评次数”只依据已结束项目的可核实反馈，可纠错，不生成信用分或自动用于排序、派单。

## 九、后续 PRD 与 UI 的验收门禁

### 9.1 PRD 不得遗漏

- 本地负责人单端边界及外部微信群边界。
- 项目、导游名单、异常、导入和导出的状态语义。
- 班级人数作为车辆、住宿、用餐共同数据源。
- 条件模块不适用时“不显示、不建数据、不导出”。
- 导入预览确认门禁、部分成功语义和错误追踪。
- 自动建议、人工调整和调整后重新校验。
- 敏感数据脱敏、操作记录、备份和恢复。
- 本文第八节的最终决策结果。

### 9.2 UI 设计不得自行增加

- 导游移动端、在线报名或抢团页面。
- 独立车辆库、司机库、酒店库、餐厅库。
- 学生个人名单。
- 自动发微信、自动投保或在线支付入口。
- 未定义结果和失败处理的快捷按钮。

### 9.3 开发任务生成条件

正式 `tasks.md` 应在以下条件满足后重建：

1. 本清单经负责人确认或完成必要修订。
2. 新版 PRD 吸收本清单并确定第八节决策。
3. 数据模型与页面字段对应关系完成检查。
4. 每个开发任务都能关联到具体页面、规则和可观察验收结果。
