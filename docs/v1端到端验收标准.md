# 研学团负责人工作台 v1 端到端验收标准

- 文档状态：`APPROVED`
- 版本：v1.0 批准版
- 更新日期：2026-09-09
- 产品依据：`prd.md`
- 页面依据：`页面字段与交互规则清单.md`
- 施工依据：`../tasks.md`
- 验收对象：本地负责人单端工作台

> 验收不是检查“任务是否写完”，而是使用同一个脱敏研学项目，通过负责人真实使用的页面和操作路径，从建立基础资料一直运行到项目完成、Excel 导出、日志追查和备份恢复。任何模块只有页面、按钮或单元测试，却没有接入完整业务链，均不得判定通过。

## 1. 验收状态与总判定

| 状态 | 含义 |
| --- | --- |
| `NOT_RUN` | 尚未执行，不得写“基本通过” |
| `PASS` | 操作、数据结果和证据全部符合标准 |
| `FAIL` | 已执行但不符合标准，必须记录复现步骤 |
| `BLOCKED` | 因明确的外部输入或决策无法执行，写明负责人和解除条件 |
| `REVIEW` | 机器结果通过，但仍需负责人判断实际业务可用性 |

v1 只有同时满足以下条件才能判定 `PASS`：

1. 主验收项目 E2E-STUDY-001 从头到尾使用同一个项目 ID，不删除重建、不换项目绕过错误。
2. P01—P20 每个页面或条件页面都完成规定操作。
3. 每个板块均完成“进入→录入/导入→保存→校验→发现异常→修正→重新校验→影响下游”的闭环。
4. 项目最终无阻断异常，所有适用模块完成，能够推进到“已完成安排”。
5. 保险、乘车、住宿、用餐四类 Excel 真实生成、实际存在、可打开且数据一致。
6. 导入、敏感查看、人工调整、导出、备份和恢复记录可追查。
7. 退出备份提醒、30 个日备份/12 个按月备份轮转和恢复在隔离验收目录中实际跑通；恢复后仍为同一个项目 ID，数据与备份时一致。
8. 自动检查、浏览器检查和负责人业务检查均有证据；只通过一种不算整体验收通过。
9. 不出现导游移动端、在线报名、独立车辆/酒店库或学生个人名单等明确不做内容。
10. PRD D01—D09 和本地访问控制方案已经确认；未确认时整体验收最高为 `BLOCKED` 或 `REVIEW`。

## 2. 验收原则

### 2.1 必须走真实用户路径

- 数据只能通过页面、正式导入入口或正式服务接口产生。
- 不允许直接修改 SQLite、浏览器存储、测试变量或源代码来修正数据。
- 不允许刷新示例数据、重新创建项目或更换项目跳过异常。
- 自动化可以代替点击，但必须使用与负责人相同的公开页面或接口。

### 2.2 同一个项目贯通

```text
学校库
  → 导游库
  → 创建项目
  → 导入行程、班级和老师
  → 生成招募通知、粘贴接龙
  → 匹配导游、处理冲突、分配班级
  → 乘车安排、超载修正
  → 住宿安排、混住修正
  → 用餐安排、桌数不足修正
  → 全项目重新校验
  → 表格预览和 Excel 导出
  → 日志核对
  → 备份、修改、恢复
  → 推进到已完成安排并返回工作台核对
```

### 2.3 数据安全

- 全部学校、人员、电话和证件均为虚构或专门生成的脱敏测试数据。
- 截图、日志和报告不展示完整测试证件值，只保留末四位或哈希。
- 备份恢复必须使用隔离验收数据库和临时目录，禁止覆盖真实业务数据。

## 6. 必做补充分支

主项目启用了住宿和用餐，因此需补一个最小项目验证“不适用”逻辑。补充分支不替代主项目贯通。

### BR-01 一日游且不含餐

1. 新建一天的测试项目，设置不住宿、不含餐。
2. 总览中住宿、用餐显示“不适用”，不是 0% 未完成。
3. 不创建住宿、用餐数据库记录。
4. P16 不显示住宿表、用餐表导出入口。
5. 完成适用模块后可进入“已完成安排”。

### BR-02 导入部分成功与修复

1. 班级 Excel 增加一行“学生总数不等于男＋女”的错误数据。
2. P12 精确定位错误行列。
3. 若 D05 允许有效行写入，批次必须为部分成功并保留失败原因。
4. 修正错误行后再次导入，不得重复写入先前成功行。
5. 若 D05 不允许部分成功，则整批不写入并明确说明。

### BR-03 班级拆车

1. 使用一个人数超过单车容量的脱敏班级。
2. 系统不得强行超载或伪造空位。
3. 拆到两车后，各车学生合计等于原班人数。
4. 乘车表保留各车实际人数和班级关联。

### BR-04 导游退团与替换

1. 在项目完成导游分配后，由负责人记录一名导游退团。
2. 填原因，记录时间和距出团天数，释放班级并产生缺口。
3. 从无冲突导游中人工选择替换。
4. 车辆导游、保险名单、住宿人数和异常同步更新。
5. 为保持主场景最终期望，可在隔离数据库副本执行。

### BR-05 删除、停用和历史引用

1. 删除被主项目引用的学校和导游时，系统阻止硬删除。
2. 停用导游后，历史项目仍显示当次安排事实。
3. 停用导游不得再进入新项目安排。

### BR-06 损坏备份恢复

1. 在隔离目录准备损坏或不完整备份。
2. 恢复必须被拒绝。
3. 当前数据库和证件目录不得半覆盖。
4. P19 记录失败及原因，但不暴露敏感路径或数据。

## 9. 必须保留的证据

### 9.1 自动证据

- 统一检查命令、退出码和完整输出。
- 日期、人数、车辆、住宿、用餐、状态和事务测试。
- SQLite 关键查询及外键检查。
- Excel 程序化回读。
- 退出提醒、备份完整性、30 日/12 月轮转结果和恢复前后数据对照。
- 敏感信息扫描。

### 9.2 浏览器证据

- 1366×768 关键节点截图或录屏。
- 每个异常产生、定位和解决前后的状态。
- 控制台错误、页面横向溢出、宽表滚动和主要按钮键盘操作记录。

### 9.3 负责人业务判断

- 下一步是否符合实际工作顺序。
- 项目、班级、导游、车辆、住宿、用餐信息密度是否可用。
- 异常说明能否让负责人知道去哪里修改。
- 四类 Excel 是否能直接用于业务复核。
- 备份、恢复和敏感查看是否清楚且不易误操作。

负责人判断未完成时，即使自动检查全绿，整体验收最多为 `REVIEW`。
